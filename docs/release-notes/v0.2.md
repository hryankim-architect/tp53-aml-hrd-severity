# v0.2, tp53-aml-hrd-severity (HRD-mutation-to-severity linkage)

Second public release. **Capability portrait, not a research result.**

## What this release adds

v0.1 shipped a TP53-only severity score with Cox HR 8.39 on n=15. The
score was branded "TP53-HRD severity" but the actual HRD axis was a
hand-wave: only TP53 tier + bi-allelic VAF proxy went into the
calculation, and the README admitted this in
`docs/what-is-out-of-scope.md` ("scarHRD signature calibration,
out of scope").

v0.2 closes that gap. The HRD axis is now a genuine **genomic-scar
score per Telli et al. 2016 (PMC6773427 / Myriad MyChoice)**, computed
in pure Python over the GDC TCGA-LAML ASCAT2 open-tier allele-specific
copy-number segment files:

```
HRD_score = LOH + TAI + LST
```

* **LOH**, segments with Minor_Copy_Number == 0, length > 15 Mb,
  NOT spanning the whole chromosome (Abkevich 2012)
* **TAI**, subchromosomal segments with allelic imbalance extending
  to a telomere, not crossing the centromere (Birkbak 2012)
* **LST**, chromosomal transitions between adjacent segments ≥ 10 Mb
  long, after smoothing across gaps < 3 Mb (Popova 2012)
* **HRD-positive** call at score ≥ 42 (Telli 2016 TNBC threshold;
  AML-specific cutoff still TBD, see scope note in
  `docs/what-is-out-of-scope.md`)

## New modules

* `src/tp53_hrd/scar.py`, Telli 2016 LOH + TAI + LST implementation
  with hg38 chromosome lengths and centromere midpoints inlined, no
  R / scarHRD dependency.
* `src/tp53_hrd/scar_data.py`, GDC files-API client that finds the
  ASCAT2 (preferred) or ASCAT3 (fallback) allele-specific segment file
  per patient and caches the download.

## Extended modules

* `src/tp53_hrd/severity.py`, new `composite_severity(tp53, hrd_score)`
  combines the v0.1 TP53 axis (weight 0.5) with the v0.2 HRD-norm axis
  (weight 0.5). Equal weighting is deliberate, AML-specific learned
  weights would need n much greater than 15.
* `src/tp53_hrd/survival.py`, new `cox_bivariate(covariates, interaction)`
  fits a multi-covariate Cox PH model with optional interaction term.
  The pipeline now runs:
  - Univariate TP53 (v0.1 baseline, unchanged)
  - Univariate HRD-scar (NEW)
  - Bivariate TP53 + HRD (NEW, is HRD additive or redundant to TP53?)
  - Interaction TP53 × HRD (NEW, synergy check)
* `src/tp53_hrd/pipeline.py`, wires ASCAT segment fetch, HRD-scar
  scoring, and bivariate Cox into the run_pipeline body. New audit
  emissions: `ascat_segments_fetched`, `hrd.scar_scores.computed`,
  `survival.bivariate_cox.computed`. Graceful skip (`hrd_scar_skipped`)
  if GDC is unreachable so the v0.1 TP53-only path still completes.

## New tests

* `tests/test_scar.py`, 12 unit tests covering LOH / TAI / LST
  edge cases and the 42-threshold call.
* `tests/test_severity_composite.py`, composite-score formula tests
  including the "TP53 + HRD layered in" round-trip.
* `tests/test_survival_bivariate.py`, synthetic 60-patient cohort
  with both axes contributing to hazard; verifies bivariate Cox
  returns per-covariate HR + the interaction term.

## Scope (downgraded from v0.1)

n=15 is severely underpowered for a 3-parameter Cox model. The pipeline
emits the bivariate and interaction results regardless because the
comparison versus the univariate baseline is what makes the addition
defensible as a capability demo. The README and release notes downgrade
the statistical language to "descriptive" / "consistent with" / "trend
toward", single-cohort claims at this sample size belong to a paper,
not a portfolio.

## What did v0.2 NOT add

See the updated `docs/what-is-out-of-scope.md`:

- R-resident scarHRD validation (deferred until reviewer requests it)
- AML-specific HRD threshold calibration (needs labelled ground truth)
- ASCAT3 / FACETS cross-caller agreement statistics
- All v0.1 out-of-scope items that were *substrate-level* (HA, RBAC,
  multi-tenant) remain out of scope.

## Reproducibility

- `make data`, unchanged from v0.1 (MAF + clinical only); ASCAT
  segment fetch is now lazy at run-time inside the pipeline so a
  network failure does not block v0.1 reproduction.
- `make run`, runs the full v0.2 pipeline including ASCAT download
  (one HTTPS call per cohort patient).
- `make test`, runs the full v0.1 test suite plus the 3 v0.2 test
  modules (scar, severity_composite, survival_bivariate).
- All tests pass without network access (the scar tests use synthetic
  segment fixtures; the only network-dependent path is the live
  `make run`).
